Stage 01 · Entrypoints & Phase Triggers

serve.py · aws_alpha.py · aws_worker.py

Local Workstation (local)

Loopback dev server (127.0.0.1:8765) with the run.html Terminal launcher and mint LOCAL header badge.

python -m leaderboard.serve --phase local

Personal AWS Staging (alpha)

Provisions a Spot i4i.2xlarge with XFS reflink=1 NVMe and private S3, then collapses all resources to $0.00/hr.

./leaderboard/aws_alpha.sh run --preset mini --collapse-after

Official Cloud Batch (prod)

Runs database adapters sequentially on dedicated cloud NVMe hardware and publishes allowlisted runs without a phase badge.

./leaderboard/aws_worker.sh --machine <id> --preset full

Stage 02 · Mutual Exclusion, Alpha Lease & Provenance Snapshot

leaderboard/.runs/

Hardware & Lease Locks

Acquires non-blocking flock on batch.lock and run.lock and verifies alpha.owner so two runs never share CPU, RAM, or NVMe.

leaderboard/.runs/{alpha,batch,run}.lock

Crash-Recovery Journals

Persists active DB names before server start. If a run is killed by SIGKILL, the next invocation replays teardown before starting.

leaderboard/.runs/<system>.{journal,active}.json

Git & Execution Profile

Captures source_snapshot(CODE_PATHS), suite_sha256, and execution_profile (local_single_host, economic_single_vm, or paper_separated_vms).

source_snapshot() · execution_profile

Stage 03 · Three Benchmark Execution Lanes

run.py · run_macro.py · run_verbs.py

3A · MICROBENCH LANE

Seeds the CH-benCHmark dataset and times 8 isolated operations across 3 independent tries on fresh bb_<id> databases.

python -m leaderboard.run <system> --machine <id>

3B · MACROBENCH LANE (S1–S6)

Executes 6 stateful agent workflows in isolated subprocesses, supporting both Full-suite and --native-only campaign modes.

python -m leaderboard.run_macro <system> --preset full --machine <id>

3C · VERB SCALING LANE (S0_verbs)

Sweeps fanout, depth, mutation_scale, and concurrency in isolated process groups with verified cleanup.

python -m leaderboard.run_verbs <system> --machine <id>

Stage 04 · Pluggable System Adapters & dblib Connectors

leaderboard/<system>/

Self-Hosted Engines

Dolt, Doltgres, MatrixOne, SeekDB, PostgreSQL FILE_COPY, and Chronos implement executable lifecycle hooks inside leaderboard/<system>/.

install → start → check → CONNECTOR → stop

Managed Cloud Services

Neon, Tiger Cloud, and Xata ("hosted": "yes") validate credentials via preflight() and record SQL round-trip latency (rtt_ms).

--client-location <loc> · rtt_ms probe

Open-Closed Repository Boundary

All orchestration, adapters, and UI assets live strictly inside leaderboard/ without modifying upstream dblib/ or benchmark logic.

leaderboard/<system>/{system.json,connector.py}

Stage 05 · Fail-Closed Validation, Cohort Grouping & Static Assembly

validate*.py · build*.py · site.py

Schema & Provenance Validators

Verifies schema_version, suite_sha256, dataset_sha256, clean teardown, and execution_profile before any record can rank.

validate.py · validate_macro.py · validate_verbs.py

Profile & Mode Cohort Builders

Partitions tables by execution_profile and native_only so single-VM, separated-VM, and local runs never mix in one ranking.

build.py · build_macro.py

Atomic Phase Bundle Swap

Builds into a staging directory and atomically swaps into leaderboard/.site/{local,alpha,prod}/.

2. Single-Run Lifecycle & Fail-Closed Teardown

Zero leftover servers

3. Benchmark Suites & Cohort Separation

BranchBench evaluates database branching across three complementary suites while strictly isolating hardware and campaign cohorts.

Agent Workflows (S1–S6)
Six stateful AI agent scenarios (rl_env, context_mgmt, multi_agent, dev_agent, ops_agent, data_agent) exercising nine Git-like verbs alongside concurrent SQL queries. Supports both Full-suite and --native-only campaign modes.
Operations (Micro)
Eight isolated operations (time_to_first_query, branch_create, branch_connect, read, range_read, insert, update, range_update) plus load_time and provision_time on a deterministic CH-benCHmark seed (leaderboard/suite.json).
Verb Scaling (S0_verbs)
Controlled micro-suite sweeping fanout, depth, mutation_scale, and concurrency via python -m leaderboard.run_verbs <system> --machine <id>.
Hardware Cohorts
Every artifact records execution_profile (local_single_host, economic_single_vm, or paper_separated_vms) and only competes inside its matching profile group.

4. Phase Guide: local · alpha · prod

All three phases run the exact same runners and validators; the phase controls only hardware target, record selection, and UI affordances.

Local Dev (local)
python -m leaderboard.serve --phase local serves http://127.0.0.1:8765/ with the run.html launcher and mint LOCAL badge, combining local runs with leaderboard.mock reference rows.
AWS Alpha (alpha)
./leaderboard/aws_alpha.sh {up,run,deploy-site,status,collapse} tags every resource with Project=BranchBenchLeaderboard, Phase=alpha, and Stack=<stack>, stages git-tracked sources with in-place rsync activation preserving lockfile inodes, retains lease ownership through artifact download and collapse, and tears down all cloud resources to $0.00/hr.
Official Cloud (prod)
python -m leaderboard.site (default prod) publishes only records listed in leaderboard/publish.json that pass full validation (clean git commit, full macro preset, and paper_separated_vms for AWS runs), omitting the phase badge and developer wizard.
