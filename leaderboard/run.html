    How a run works

    1. Validate. Check for committed sources, all six workflows, a runnable system and a free port. Nothing runs if a check fails.
    2. Run each workflow. Seed the workflow’s own database, run its steps and record the completion time.
    3. Verify and clean up. Check the workflow’s results, delete its database and save the attempt’s evidence as JSON.
    4. Rebuild. Rebuild the leaderboard. A run that fails validation is listed below the board with its reason.
    1. Prepare and load. Create a temporary database and load the shared dataset.
    2. Measure. Time branch, read and write operations with identical settings.
    3. Clean up and save. Remove the run’s resources and save timings and run details as JSON.
    4. Rebuild. Rebuild the leaderboard from valid results. Incompatible history is listed with its reason.
    How results reach the leaderboard

    The runner saves a JSON result for each database: timing attempts, load and setup times, and environment details. python -m leaderboard.site --phase local validates every result on this machine, lists incompatible or failed runs with their reasons, and builds this machine’s site under leaderboard/.site/local/. Historical result files are kept.

    Results stay on your machine. The published site is assembled separately from the records named in leaderboard/publish.json; nothing run from this page is published by it.
