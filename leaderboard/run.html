    Enable one-click runs

    Start the local development server once from the repository root, then open the wizard it serves. The default production phase has no wizard or launcher.

    python -m leaderboard.serve --phase local

    A file preview can show scripts, but cannot open Terminal on its own.

    Runs are sequential and stop on a failed command. Commit source changes first. Terminal prompts for missing service credentials with input hidden.

    How a run works.

    8workloads / database
    3tries each
    1. 01
      Prepare & load

      Create a temporary database and load the shared dataset.

    2. 02
      Measure

      Time branch, read, and write workloads with identical settings.

    3. 03
      Clean up & save

      Remove run resources and save timings and run details as JSON.

    4. 04
      Validate & compare

      Rebuild from valid current-suite results; exclude incompatible history.

    How results reach the leaderboard

    The runner saves a JSON result for each database: timing attempts, load and setup times, and environment details. python -m leaderboard.site --phase local validates every result on this machine, excludes incompatible or failed runs with their reasons, and generates the development site under leaderboard/.site/local/. Historical result files are kept.

    Results stay on your machine. The production site is assembled separately from the records named in leaderboard/publish.json; nothing run from this wizard is published by it.
